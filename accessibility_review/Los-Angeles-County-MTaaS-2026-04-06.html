Summary of Findings

Page Sections

In our assessment of the tested webpages, we encountered certain page aspects that reoccurred sitewide. In order to provide you with succinct test results, please find our results for these page sections below. Each individual page test report will list the Page Sections present on that page, and the individual Page reports will focus on the unique issues present on that page. It has been our experience that most customers can address issues found on the individual Page reports immediately, though they need expertise from developers to address the issues found in the Page Sections.

Websites

Test Case Result Comments

All interactive elements are actionable when navigating without a mouse.

2.1.1 Keyboard (Level A)
Fail

  • The "Service Delivery" expanded dropdown options are not accessible to keyboard and screen-reader users because they are coded as div elements with a role="listbox". While this role is necessary to inform users of the element's purpose, it doesn't automatically add these elements to the focus order or provide keyboard interactivity. We recommend coding this as a HTML select element instead to ensure it receives native focus, or add the appropriate tabindex and keyboard event listeners to the elements.

  • The "Sort Results By" expanded dropdown options are not accessible to keyboard and screen-reader users because they are coded as div elements with a role="listbox". While this role is necessary to inform users of the element's purpose, it doesn't automatically add these elements to the focus order or provide keyboard interactivity. We recommend coding this as a HTML select element instead to ensure it receives native focus, or add the appropriate tabindex and keyboard event listeners to the elements.

The navigation order is logical and intuitive.

2.4.3 Focus Order (Level A)
Fail

  • When keyboard and screen-reader users activate the "Service type" dropdown, users' focus isn't taken to the newly revealed content. The expanded dropdown menu appears at the end of the DOM, which means users would need to navigate through all of the page content first, to encounter these options. We recommend either moving the content higher in the DOM, so users can follow the natural focus order, managing the user's focus so that they are taken to the first element in the expanded dropdown, or use a semantic HTML select element which will automatically handle most of the accessibility features and focus management.

Structure, information, and relationships are programmatically determined or available as text.

User interface controls, parts of graphics needed to understand content, and focus states have a color contrast ratio of 3:1 against adjacent color.

1.4.11 Non-text Contrast (Level AA)
Fail

  • In the "Los Angeles County" map, the orange (#F29345) location dots have a 1.65:1 contrast ratio with the muted orange (#DCD9D6) background, which falls short of the 3:1 requirement.

  • The "An Organization" unchecked radio input, "Location", "Service Type", "Service Delivery" and "Sort By Results" grey (#DEE2E6) borders have a 1.65:1 contrast ratio with the light grey (#FAFAFA) background, which falls short of the 3:1 requirement.

  • The "Location," "Service Type," "Service Delivery," and "Sort Results By" elements have very thin dark blue (#86B7FE) focus outlines that have a 1.25:1 contrast ratio with the white (#FFFFFF) background, which falls short of the 3:1 requirement.
